SECTION 1: PROJECT PLANNING

1.1 Executive Summary & Problem Formulation

Traditional fashion e-commerce platforms often deliver static, cookie-cutter shopping experiences lacking emotional connection, interactive visual engagement, and real-time fulfillment visibility. High-end couture brands require interactive visual merchandising, transparent order fulfillment, and a live Content Management System (CMS) allowing marketing managers to update promotional banners, 3D cylindrical carousels, FAQs, and client metrics without writing code or redeploying the server.

Core Mission: Build a high-performance luxury retail platform unifying 3D cylindrical community carousels, dynamic color-variant image switching, live GPS driver delivery telemetry, and an integrated Cloudinary media CDN.

SECTION 2: DATABASE DESIGN

2.1 Normalization & Architectural Principles

The database follows strict Third Normal Form (3NF) guidelines:

  • Atomic Attributes (1NF): No multivalued or repeating group columns. Complex attributes (such as color mapping and gallery URLs) leverage native JSON columns with indexable keys.
  • Full Functional Dependency (2NF): All non-key attributes depend entirely on table primary keys.
  • Transitive Independence (3NF): No non-key attributes depend on other non-key attributes. Category names reside strictly in categories, referenced via foreign keys.

2.4 Indexing & Query Acceleration Strategy

-- Fast slug and identifier lookups
CREATE UNIQUE INDEX idx_categories_slug ON categories(slug);
CREATE UNIQUE INDEX idx_products_slug ON products(slug);
CREATE UNIQUE INDEX idx_users_email ON users(email);
CREATE UNIQUE INDEX idx_orders_number ON orders(order_number);

-- Relational foreign key indexers
CREATE INDEX idx_products_category_id ON products(category_id);
CREATE INDEX idx_products_price ON products(price);
CREATE INDEX idx_order_items_order_id ON order_items(order_id);
CREATE INDEX idx_reviews_product_id ON reviews(product_id);

-- Operational dispatch queries
CREATE INDEX idx_orders_delivery_status ON orders(delivery_status);
CREATE INDEX idx_orders_created_at ON orders(created_at DESC);

2.5 ACID Transactional Implementation

To ensure strict transactional integrity during multi-item checkouts:

  • Atomic Rollback: Database mutations are executed inside DB::transaction(). If payment processing fails or stock is exhausted mid-checkout, all modifications to orders, order_items, and products are automatically rolled back.
  • Immutable Receipts: Product names and sale prices are snapshotted directly into order_items. Subsequent catalog price adjustments never mutate past historical transactions.
